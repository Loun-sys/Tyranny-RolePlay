# Tyranny — русская текстовая RPG для Discord

Discord-бот переносит основные системы **Tyranny** в удобный текстовый формат. Проект создан на базе интерфейсных решений бота «Крысиный Рейх», но использует отдельный код, базу и каталог. Исходный бот «Крысиный Рейх» не изменяется.

## Реализовано

- русская регистрация Вершителя Судеб: происхождение и две разные специализации;
- шесть характеристик: Сила, Искусность, Быстрота, Живучесть, Смекалка и Стойкость;
- 22 оружейных, вспомогательных и магических навыка с автоматическим расчётом базовых значений;
- стартовые бонусы и способности всех десяти специализаций;
- здоровье, раны, уровни и опыт;
- все 121 канонический талант шести деревьев Вершителя: Лидерство, Защита, Сила, Ловкость, Дальний бой и Магия;
- объединённый русско-английский каталог Tyranny Wiki: английские записи переводятся на русский, ссылки и оригинальные изображения сохраняются;
- личный инвентарь, стопки расходников и выдача предметов мастером;
- слоты головы, торса, рук, ног, двух аксессуаров, четырёх оружейных наборов и четырёх быстрых предметов;
- проверка совместимости предмета и слота, а также занятости обеих рук двуручным оружием;
- гримуар и создание всех 64 допустимых формул из 71 русифицированного сигила; названия и полные описания берутся из официальной русской локализации;
- переведённый справочник английской Wiki о развитии персонажа, магии, экипировке, репутации, Эдиктах и Шпилях;
- независимые шкалы Благосклонности и Гнева для основных фракций и Архонтов;
- действующие Эдикты Кайрос и сеть Шпилей с улучшениями;
- полностью кнопочная боевая сцена: лобби, присоединение игроков, создание противников, автоматический порядок действий по восстановлению, выбор цели, обычные атаки, способности, заклинания, расходники и смена оружейных комплектов;
- автоматические броски Точности против нужной защиты, четыре качества попадания, броня, пробивание, тип урона, синхронизация здоровья и опыт применяемого навыка;
- PNG-карточка Вершителя Судеб на бронзовом пергаменте с портретом, характеристиками, здоровьем, навыками и экипировкой;
- механики спутников намеренно отсутствуют.
- веб-конструктор в стиле архива Тунона с контекстными подсказками, портретом и каноническим распределением 68 пунктов характеристик и 20 дополнительных очков навыков;
- `/регистрация` создаёт приватную одноразовую ссылку на два часа, а готовая анкета сохраняется напрямую в базе бота.
- публичный веб-архив показывает всех созданных персонажей, а кнопка «Личное дело» выдаёт владельцу защищённую ссылку на 30 дней;
- веб-кабинет и Discord используют одну базу: уровень выдаёт очки характеристики и таланта, изменения на сайте немедленно видны боту;
- в кабинете доступны деревья всех талантов, конструктор заклинаний, экипировка и инвентарь; вместимость сумки растёт от Атлетики, мелкие предметы слотов не занимают.
- шесть новых предысторий открывают личные ветки Лантри, Эбб, Смерти из Тени, Сирин, Фуги или Барика в дополнение к базовым деревьям Вершителя;
- отдельная страница фракционных талантов показывает Благосклонность, Гнев, ранги репутации и автоматически открытые способности;

## Быстрый запуск

Требуется Python 3.11 или новее.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python bot.py
```

В `.env` задаются:

```env
DISCORD_TOKEN=секретный_токен
DISCORD_GUILD_ID=сервер_для_мгновенной_синхронизации
TYRANNY_DATA_DIR=data
TYRANNY_MASTER_ROLE_IDS=идентификатор_роли_мастера
```

Токен нельзя публиковать или добавлять в Git. Пользователь с правом «Управлять сервером» или «Администратор» автоматически считается мастером.

Статический конструктор и архив находятся в `web/` и автоматически публикуются на GitHub Pages через `.github/workflows/pages.yml`. GitHub хранит только интерфейс: одноразовые и личные ссылки проверяет HTTP API самого бота. Для сохранения задаются `TYRANNY_REGISTRATION_URL`, `TYRANNY_PUBLIC_API_URL` и `TYRANNY_WEB_ORIGIN`; `TYRANNY_ARCHIVE_URL` необязателен и по умолчанию вычисляется как `archive.html` рядом с конструктором.

Закрытая мастерская находится в `web/admin.html`. Команда `/админ` доступна только участникам с правом администратора, правом управления сервером или ролью из `TYRANNY_MASTER_ROLE_IDS`; она выдаёт личную отзываемую ссылку на восемь часов. Все изменения анкет записываются в журнал `admin_audit`. `TYRANNY_ADMIN_URL` необязателен и по умолчанию вычисляется рядом с конструктором.

## Каталог Wiki

Русский снимок находится в `catalog/tyranny_catalog.json`, переведённый английский слой — в `catalog/tyranny_catalog_en_ru.json`, а полный проверочный источник из 1 224 английских страниц — в `catalog/tyranny_wiki_en.json`. Рабочее обновление сохраняется в постоянный каталог `data`.

```powershell
python wiki_importer.py --database data/tyranny.sqlite3 --snapshot catalog/tyranny_catalog.json
python english_wiki_source.py --output catalog/tyranny_wiki_en.json --reuse-index
python import_english_catalog.py
```

Импортёры читают русские и английские категории оружия, брони, щитов, аксессуаров, расходников, еды, зелий, материалов, свитков и сигилов. В локальной базе сохраняется прямая HTTPS-ссылка на изображение Fandom; сами медиафайлы не дублируются. Технический английский источник не показывается игрокам.

Канонический словарь `catalog/official_game_localization.json` собирается по одинаковым ID английских и русских StringTable установленной игры. Он содержит 10 270 строк, 2 341 связанную игровую сущность и все формулы заклинаний. После обновления локальных ресурсов каталоги предметов можно повторно дополнить официальными названиями и предысториями:

```powershell
python scripts/extract_official_localization.py
python scripts/enrich_item_localization.py catalog/tyranny_catalog_en_ru.json catalog/tyranny_catalog.json
```

## Railway и Docker

Проект запускается как один Railway-сервис: Discord-бот и HTTP API работают в одном контейнере. Подключите постоянный Volume к `/app/data`, установите `TYRANNY_DATA_DIR=/app/data`, добавьте переменные окружения и создайте публичный домен для API на порту `8080`.

```powershell
docker compose up -d --build
```
